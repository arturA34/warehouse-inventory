# Замеры клиента склада

Стенд открывает окно Avalonia и пользуется теми же моделями представления, что настольный клиент. Он создаёт 100 000 товаров, 10 складов и 120 000 движений за квартал и день перед кварталом. Один клиент отображает результат, ещё 19 одновременно выполняют поиск под отдельными учётными записями.

```powershell
dotnet run --project tools/Warehouse.Timings -c Release -- --client
```

Для каждого оконного сценария выполняется один прогрев и пять замеров. Таймер останавливается на втором запросе кадра Avalonia после изменения, когда окно уже обработало первый кадр с результатом. Это время до обработки кадра приложением. Программа проверяет появление нужного экрана, размер выдачи и строки отчёта.

| Сценарий | Что измеряется | Цель |
| --- | --- | --- |
| Вкладка документов | От переключения вкладки до обработки кадра с экраном | 150 мс |
| Поиск | От запуска поиска `SKU-09` до обработки кадра с первой страницей из 25 товаров | 400 мс |
| Квартальный отчёт | От запуска формирования оборотов до кадра с таблицей из 100 000 строк | 3 с |
| Сохранение | Формирование Excel и запись на локальный диск. Три повтора без ожидания выбора файла | Отдельный замер |

## Результаты 27 ноября 2026 года

Обе проверки выполнены на Intel Core i5-9300HF с 8 логическими процессорами и .NET 10.0.1. Windows сборки 26300 имела 8112 МиБ доступной памяти, Ubuntu 26.04 LTS в WSLg — 3876 МиБ. Данные находились в памяти без сети и подключения к БД. Для дискового замера использовалась временная папка каждой ОС.

| Сценарий | Windows, медиана / максимум | Ubuntu, медиана / максимум |
| --- | --- | --- |
| Вкладка документов | 22,8 / 42,3 мс | 29,4 / 52,4 мс |
| Поиск | 61,4 / 1029,4 мс | 71,5 / 138,7 мс |
| Квартальный отчёт | 2594,1 / 2928,3 мс | 2532,3 / 4832,6 мс |
| Формирование и сохранение Excel | 5735,5 / 9863,9 мс | 7057,9 / 10285,2 мс |

На Windows максимальное время поиска превысило 400 мс при одновременном запуске 19 фоновых поисков. Замер охватывает вызов каталога, конкуренцию за блокировку хранилища в памяти и обработку кадра. Длительность этих этапов в этом запуске измерена суммарно. На Ubuntu квартальный отчёт превысил 3 с при такой же фоновой нагрузке. Участок замера охватывает чтение движений, сборку 100 000 строк и отображение таблицы. Для локализации превышения нужно повторить измерения с отдельными отметками на границах этих этапов.

## Приёмочный замер

Повторить сценарии на Windows и Linux с подключёнными SQLite и PostgreSQL. Для SQLite зафиксировать расположение файла и условия локального режима. Для PostgreSQL зафиксировать хост базы, тип подключения и задержку сети. Для каждого запуска записать ОС, процессор, память, версию клиента, глубину истории, количество клиентов, медиану и максимум. Сопоставить замеры слоя хранения с оконными замерами для каждого превышения.

Стенд сейчас использует хранилище в памяти. Для приёмочного замера нужны адаптеры и данные по задачам #1–#6.
